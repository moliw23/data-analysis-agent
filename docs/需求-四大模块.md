# 四大功能模块 · 开发需求规格（PRD）

> 适用项目：`data-analysis-agent`（Vite + React 18 + ECharts + 自研统计引擎 `engine.js`）
> 文档用途：在动手编码前，明确各模块的核心目标、实现范围、边界条件、输入输出规范与关键约束。
> 设计基调（全模块必须遵守）：低饱和淡紫主色 `#8B7EC8`/`#8b5cf6`、mobile-first、≥40px 触控热区、安静专业的 UI，禁用夸张渐变与营销化表达。
> 全局铁律（全模块必须遵守）：**所有数字由 `engine.js` 真实计算**；LLM 只做「规划 / 解释 / 生成 SQL 文本」，严禁让模型口算数字。

## 模块一：暗色模式 + PPTX 导出

### 1.1 核心目标
- 以**低成本**实现高体验：暗色模式靠 CSS 变量覆盖，PPTX 靠复用现有 `chartsToPNGs` + 引入 `pptxgenjs`。
- 支持界面主题切换（浅色 / 暗色 / 跟随系统），并持久化用户偏好。
- 支持把当前分析结果导出为**可编辑**的 `.pptx` 文件（文字、表格、图表图片均可在 PowerPoint/WPS 中二次编辑）。

### 1.2 实现范围
**1.2.1 暗色模式**
- 在 `styles.css` 增加 `[data-theme="dark"] { … }` 覆盖块，重定义 `--bg/--surface/--fg/--muted/--border` 等变量（背景 `#1A1720` 系、前景 `#E9E6F0` 系、边框低对比）。
- 新增 `ThemeContext`（或轻量主题 state + `document.documentElement.setAttribute('data-theme', …)`）。
- 主题切换入口：设置页（新增「主题」选项）+ 看板/报告页便捷切换按钮；三种模式：浅色 / 暗色 / 跟随系统（`matchMedia('(prefers-color-scheme: dark)')`）。
- 偏好持久化到 `localStorage`，启动时读取。
- **图表适配**：`EChart` 组件需在主题变化时重新 `setOption`（前景/坐标文字/分割线取 CSS 变量值），并触发 `resize()`；地图、热力图同此机制。

**1.2.2 PPTX 导出**
- 新增 `reportExport.js` 的 `exportPPTX(analysis, table, quality, { fileName, theme })`：
  - 复用 `chartsToPNGs()`（已存在）把图表离屏渲染为 PNG；
  - 用 `pptxgenjs` 生成幻灯片：封面页、结论页（文本框）、图表页（图片 + 标题 + 口径文本）、质量页（表格）、数据预览页（表格前 N 行）。
- 导出按钮挂到：报告页、看板页、预览页（与现有 Word/PDF/HTML 并列）。

### 1.3 边界条件
- 暗色模式下**打印/PDF 导出强制浅色**（避免黑底打印费墨且不可读）——PDF 走系统打印，独立于界面主题。
- 第三方资源（如中国地图 GeoJSON）不受主题影响，仅图表描边/文字随主题。
- PPTX 图表数量上限与 Word 一致（取前 6 张），超出部分在 PPTX 内省略并提示。
- 主题切换**不刷新数据、不重跑分析**，只改视觉层。

### 1.4 输入输出规范
- **暗色模式输入**：用户操作（切换/跟随系统）+ 持久化值（枚举 `light|dark|system`）。
- **暗色模式输出**：`<html data-theme="…">` + CSS 变量生效；`EChart` 收到主题变更并重绘。
- **PPTX 输入**：
  ```ts
  exportPPTX(
    analysis: { charts: ChartSpec[]; insights: Insight[]; sampled?: {enabled,total,used} },
    table: { columns: Col[]; rows: Row[] },
    quality: { score: number; issues: Issue[] },
    opts: { fileName?: string; theme?: 'light'|'dark' }
  ): Promise<void>  // 触发浏览器下载 .pptx
  ```
- **PPTX 输出**：符合 Office Open XML 的 `.pptx` 文件；所有文字为可编辑文本框，图表为可移动/替换的 PNG 图片，表格为原生 PPTX 表格。

### 1.5 关键约束
- `pptxgenjs`、`alasql`（若启用）必须与 `echarts`/`xlsx` 一致走 `import()` **动态加载**，首屏 bundle 不膨胀。
- 暗色模式**零组件重写**：任何组件不得写死颜色，颜色一律引用 CSS 变量（现有代码已符合，新增代码强制遵守）。
- PPTX 中数字必须与界面/Word/PDF **完全一致**（同源自 `analysis`，不重新计算）。
- 主题状态在 `App` 顶层统一管理，向下透传；不得出现多份主题 state 不一致。

## 模块二：大文件流式解析

### 2.1 核心目标
- 支持**超大文件**（目标 ≥ 100MB / ≥ 100 万行 CSV、≥ 50MB JSON）的分块、流式读取与解析。
- 解析过程**主线程不卡顿**（Web Worker / 流式 reader），避免内存溢出（OOM）。
- 边解析边展现进度与数据预览，解析完成前用户可感知状态、可取消。

### 2.2 实现范围
- **CSV / JSON(行/NDJSON)**：`File.stream()` + `ReadableStream` 分块读取 → Worker 内增量解析（CSV 用带 `step` 回调的解析器，如 `PapaParse` 流式模式；JSON 按行切割）。
- **Excel(.xlsx)**：首版仍用 `SheetJS`，但置于 Worker 中执行并给出解析进度（SheetJS 原生非真流式，标注为「兼容模式」，后续可换 `ExcelJS` 流式读）。
- **增量产物**：解析中实时更新「已读行数 / 进度% / 预览前 50 行」；全量 `rows` 在 Worker 内聚合并回传主线程（或超阈值时直接落 IndexedDB，主线程只持采样）。
- **落盘**：解析完成的整表写入 IndexedDB（复用 `datasetStore.js`），支持后续断点续用。
- **取消 / 超时**：提供「取消解析」按钮；超时（如 > 5min）自动降级为采样模式并提示。

### 2.3 边界条件
- **内存上限**：主线程常驻行数设软上限（如 20 万行）；超过则仅保留采样 + 全量落盘，预览提示「已流式处理 N 行，预览基于采样」。
- **编码**：默认 UTF-8；CSV 带 BOM 自动识别；GBK 文件提供编码选择（降级，非首版必做）。
- **格式容错**：CSV 列数不齐 → 按最大列补齐，缺列置空并记质量项；引号/转义错误行 → 跳过并计数告警。
- **单文件上限**：设硬上限（如 2GB），超限直接拒绝并提示分片。
- **非表格文件**（如图片/PDF）：解析前由扩展名/MIME 预检拒绝。

### 2.4 输入输出规范
- **输入**：`File` 对象（来自上传控件）+ 解析选项 `{ type?: 'auto'|'csv'|'json'|'xlsx'; encoding?: 'utf-8'|'gbk'; maxRows?: number }`。
- **输出**（主线程接收）：
  ```ts
  {
    columns: Col[],
    rows: Row[],            // 受内存上限约束，可能仅为采样
    totalRows: number,      // 真实总行数（流式累计）
    sampled: { enabled: boolean; used: number; total: number } | null,
    previewRows: Row[],     // 前 50 行用于即时预览
    qualityIssues: Issue[], // 流式阶段发现的格式问题
    storeId?: string        // IndexedDB 落盘 ID（全量）
  }
  ```
- **进度事件**：`onProgress({ readBytes, totalBytes?, rows, phase })`。

### 2.5 关键约束
- 解析**必须**在 Worker 内，主线程仅做渲染与进度展示；Worker 与现有 `engine.js` 的 `parseCSVText` 保持算法一致（或抽公共纯函数供 Worker import）。
- 不破坏现有 `parseFile` 小文件同步路径（< 5MB 仍走原逻辑，保持简单）。
- 解析结果结构 `{columns, rows}` 必须与现有 `engine.js` 全量 API 兼容（下游 `analyze`/`manualChart` 零改动）。
- 禁止把整文件一次性 `readAsText` 读进内存（这是当前潜在 OOM 风险点，必须改流式）。

## 模块三：分析模板复用

### 3.1 核心目标
- 提供「保存 / 加载 / 分享」分析模板机制，把一次分析的可复用配置沉淀下来，**减少重复配置**。
- 模板尽量**跨数据集复用**（按「语义角色」而非「具体列名」绑定），让 A 表做的模板能套到同结构的 B 表。

### 3.2 实现范围
- **保存模板**：把当前分析配置序列化为 `AnalysisTemplate`：
  - 来源：`analyze` 的计划 / `manualChart` 的 `spec` / 工具箱选择 / 当前筛选器 `activeFilters` / 数据源的 **schema 描述**（列名+类型+语义，非数据）。
  - 列引用采用「语义角色映射」：`{ role: 'measure', semantic: 'number', match: 'name-contains:金额|price' }` 或「按位置/类型匹配」，避免硬编码列名。
- **模板库 UI**：设置页 / 看板页「我的模板」列表（名称、创建时间、适用表结构摘要、删除/重命名）。
- **加载模板**：选数据集 → 自动按 schema 把模板的语义角色映射到当前表的真实列 → 重跑 `analyze` / 应用 `manualChart` spec / 恢复筛选器。映射失败项高亮提示，用户可手动指派。
- **分享模板**：导出为 `.json` 文件（不含任何原始数据，仅配置+schema 描述）；导入即入库。首版**不做云端同步**（保持本地 + 文件分享）。
- **持久化**：`localStorage`（模板体积小）；可选同步进 IndexedDB。

### 3.3 边界条件
- 模板**不含原始数据**，仅含配置 + schema 描述（防泄露、防体积爆炸）。
- 数据集结构不兼容（如模板要求数值 measure 但目标表无数值列）→ 加载时**阻断并说明缺失角色**，不静默跑出空结果。
- 模板版本号（`v: 1`），未来引擎变更时做兼容/迁移；无法迁移的旧模板标记「需手动修复」。
- 个人模板**不跨用户、不上云**（除非后续接入账号体系）。

### 3.4 输入输出规范
- **保存输入**：`{ name: string; config: AnalysisConfig; schemaFingerprint: SchemaFingerprint }`。
- **模板结构（输出/落库）**：
  ```ts
  AnalysisTemplate = {
    id: string; v: 1; name: string; createdAt: string;
    config: {
      plan?: AnalysisPlan;            // analyze 计划
      charts?: ChartSpec[];           // manualChart 规格（列用 role 引用）
      filters?: FilterSpec[];         // 语义化筛选
    };
    schemaFingerprint: { columns: {name,type,semantic}[] };  // 用于兼容性校验
  }
  ```
- **加载输入**：`templateId` + 目标 `table`（含 schema）。
- **加载输出**：`{ appliedConfig, mapping: {role→realCol}, unresolved: role[] }` → 驱动重跑。

### 3.5 关键约束
- 模板的「列绑定」**必须用语义角色**，禁止存储裸列名（否则无法跨表复用，违背核心目标）。
- 加载时若 100% 角色可映射，静默应用；若有 unresolved，必须交互式让用户指派，**不得**用错误数据硬跑。
- 模板库与现有 `analyze` / `manualChart` / `applyFilters` 是**纯消费关系**，不修改引擎逻辑。
- 导出文件须可被他人「导入即用」，schema 描述要自包含（含语义类型）。

## 模块四：深度 NLP 问答（Text-to-SQL）

### 4.1 核心目标
- 用户用**自然语言**提问（如「2024 年各省份销售额总和，按降序排前 10」），系统自动生成**可执行 SQL** 并运行，返回结果与图表。
- 从「规则式扫表（`chatAnswer`）」升级为「语义解析 → SQL 生成 → 真实执行 → 结果解释」的闭环。
- 严格延续铁律：**SQL 由 LLM 生成文本，数据由引擎/SQL 引擎真实执行，模型不碰原始数字**。

### 4.2 实现范围
- 新增 `llmProvider.js` 钩子 `textToSQL(schemaSummary, question)`：
  - system prompt 限定：仅输出 `{"sql": "...", "explanation": "...", "chartHint": "bar|line|pie|table|none"}`；
  - 列名只允许来自 `schemaSummary`；强制 `SELECT` 且仅查询给定表。
- **执行后端 A（内存表，默认 / 离线）**：用 `alasql`/`sql.js`（动态 import）对当前 `table.rows` 建临时表执行 SELECT，返回 `{columns, rows}`。
- **执行后端 B（数据库直连）**：若当前数据源来自 `db-proxy`，把生成的 SQL 经 `queryViaProxy` 转发执行（复用现有代理）。
- **结果呈现**：执行结果 → 走现有 `analyze` / `manualChart` 的 `chartHint` 分支生成图表 + 用 `narrateInsights` 生成中文解释；展示「生成的 SQL」（可复制、可手动改后重跑）。
- **降级**：未配置 LLM 时，回退到现有 `chatAnswer` 规则式（保持可用，标注「基础模式」）。

### 4.3 边界条件
- **只允许只读 SELECT**：执行前做白名单校验——拒绝含 `INSERT/UPDATE/DELETE/DROP/ALTER/TRUNCATE/CREATE/EXEC/` 及分号多语句的 SQL；内存引擎侧也禁用写操作。
- **列名白名单**：SQL 中表/列必须存在于 schema，否则拒绝并提示「未识别的列：X」。
- **单表优先**：首版仅支持单表查询；多表需 join 的复杂问题，返回「暂不支持多表，请先使用关联功能」或退化为单表近似。
- **结果集上限**：SELECT 结果行数上限（如 5000），超出提示并截断（或提示加 `LIMIT`）。
- **超时**：LLM 生成 > 15s 或执行 > 10s → 超时提示，不阻塞界面。
- **不透明数据不外发**：内存表查询**不把数据发往任何远端**；仅数据库模式才走用户本机代理。

### 4.4 输入输出规范
- **输入**：`{ schemaSummary: SchemaSummary; question: string; backend: 'memory'|'db'; dbConnection?: ConnectionRef }`。
- **LLM 输出（结构化）**：
  ```ts
  { sql: string; explanation: string; chartHint: 'bar'|'line'|'pie'|'table'|'none' }
  ```
- **执行输出**：
  ```ts
  { ok: boolean; columns: Col[]; rows: Row[]; sql: string; explanation: string;
    chart?: ChartSpec; error?: string; mode: 'llm'|'mock' }
  ```
- **展示**：问题 + 生成的 SQL（可编辑重跑）+ 结果表 + 图表 + 中文解释 + 口径说明。

### 4.5 关键约束
- SQL **生成与执行分离**：LLM 只产出 SQL 文本字符串，绝不直接返回数字答案；数字 100% 来自 SQL 引擎执行结果。
- 内存表执行必须走 `alasql`/`sql.js`，**不得**用 `eval`/`Function` 拼执行（安全红线）。
- 生成的 SQL 必须可审计、可复制、可手改——用户应对自己的查询有完全掌控。
- 复用现有 `withLLMFallback` 降级机制；未配置 LLM 时优雅回退，不报错白屏。
- 与模块三（模板）可结合：把「问题→SQL」也可存为模板的一种（问答型模板）。

## 附录 B：推荐实施顺序与里程碑

1. **① 暗色模式 + PPTX**（低风险、高体验、纯新增）——建议先行，验证主题变量体系与动态 import 模式。
2. **② 大文件流式解析**（中等风险，需 Worker）——解决 OOM 隐患，独立于其他模块。
3. **③ 分析模板复用**（低风险，纯消费引擎）——提升复用效率。
4. **④ Text-to-SQL**（中高风险，依赖 LLM 配置 + SQL 安全）——放最后，需重点测试 SQL 白名单。

> 每完成一个模块，沿用既有验证手段：engine 逻辑脚本（`scripts/verify-*.mjs`）+ 首屏 `renderToStaticMarkup` SSR 冒烟 + `vite build`（rollup 严格校验缺失导出）+ dev server HTTP 200。
