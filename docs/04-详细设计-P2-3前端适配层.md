## 1. 目标（Spec §1.1 双形态硬验收）

后端在线时 4 钩子走网关；后端离线时 9 视图与 4 钩子**全部回退可用**；收到 4030 展示切档引导且**不自动重试**；状态条明示双形态。

## 2. 新增模块（单文件 ≤300 行，依赖只向下）

```
src/backend/client.js    # fetch 封装：信封解包 / 业务错误归一化 / request_id 透传
src/backend/probe.js     # 健康探测(1.5s 超时) + capabilities 缓存 + zustand 微状态
src/backend/gateway.js   # 网关路由：taskKey → POST /llm/chat；供 llmProvider 调用
src/components/ModeBanner.jsx      # 双形态状态条（顶栏下方）
src/components/PrivacyIndicator.jsx# 隐私档位指示器（解释入口，非标签）
```

### 2.1 client.js

- `apiFetch(path, {method, body, confirm, timeoutMs})` → 解包 `{code,message,data,request_id}`。
- `code === 0` 返回 `data`；否则 throw `BackendError{code, message, data}`（4030 时 `data` 含 current_mode/required_modes/setting_path）。
- 超时默认 10s；`AbortController`；网络错误归一化为 `BackendError{code:-1, kind:'network'}`。
- base URL：`localStorage['data-agent.backend.base'] || 'http://127.0.0.1:8000'`。

### 2.2 probe.js（唯一状态真相源）

- zustand store：`{ status: 'checking'|'online'|'offline', capabilities: null|object, privacyMode: 'strict'|'standard'|'full', lastProbeAt, error }`。
- `probeNow()`：`GET /api/v1/health`（超时 **1500ms**）→ 成功则并发 `GET /api/v1/capabilities` 缓存。
- 触发时机：App 挂载时；每 30s 定时重探；`document.visibilitychange` 回到可见时；ModeBanner「重试」手动触发。
- **export `subscribeBackend(cb)` 不引入——组件直接 `useBackendStatus()` hook 消费**。

### 2.3 gateway.js + llmProvider 集成（最小侵入）

- `gatewayChat(taskKey, messages)` → `POST /api/v1/llm/chat` body `{taskKey, messages}`；返回 `data.content`（string）；provider 未配置抛 `BackendError(4010)`。
- taskKey 映射（与 openapi 对齐）：`plan_analysis` / `narrate_insights` / `parse_question` / `text_to_sql`。
- **集成点：`llmProvider.chatJSON` 前插一级**，链路变为：
  `网关（后端在线且已配 provider）→ 直连（本机 Key 配置）→ mock 规则`。
- 判定顺序（每个钩子调用时实时读取，避免状态过期）：
  1. `useBackendStatus.getState().status === 'online'` 且 `capabilities.llm.gatewayEnabled !== false` → 尝试网关；
  2. 网关抛 4010（后端未配 provider）**立即**落回直连，不弹错（静默降级到本地直连是产品语义：后端没配 Key 不代表用户没配 Key）；
  3. 网关抛 4020/网络错 → 落回直连，`reason` 记入返回值；
  4. 网关抛 **4030 → 不落回、不自动重试**：抛给上层展示切档引导（`narrate_insights` 属纯本地统计改写不受闸门控，实际仅 text_to_sql/plan 可能触达）。
- 铁律不变：网关只转发与记账；SQL 仍由前端 sqlEngine 执行，数字仍由 engine 算。

### 2.4 ModeBanner（AC-15/16）

- `status==='checking'`：不渲染（避免闪条）。
- `online`：单行细条「本地服务已连接 · 隐私档位：strict」+「说明」icon（title 含 capabilities 摘要）。降级能力（rag.enabled=false 等）在条内列徽标，**禁止静默**。
- `offline`：条内明示「本地模式——AI 记忆/知识库/服务端调度不可用」+ 两个动作：`重试`（probeNow）、`启动指引`（title/展开说明 `cd backend && python run.py`）。
- `privacyMode` 变更由 probe 缓存驱动；PUT 档位成功后调用 `refreshCapabilities()`。

### 2.5 PrivacyIndicator（AC-29：解释入口，非标签）

- 顶栏右侧常驻按钮：档位名 + 盾形 lucide 图标（`ShieldCheck`）。
- 点击展开 popover（不弹模态）：当前档位 / 三档各自含义一句话 / 被阻断能力清单 / `去设置` 跳转 settings 视图。
- **AC-31**：三档不使用红黄绿价值编码——统一中性色，仅选中态用 `--accent`。
- 设置页档位区块本波先落指示器与跳转；完整 SettingsPanel 区块（含历史列表）在后续波次。

## 4. 测试（Vitest，jsdom）

`src/__tests__/backend.test.js`：
1. client：code=0 解包 / 4030 抛 BackendError 且带 data / 网络错误归一化。
2. probe：fetch mock 在线→online+capabilities；超时→offline；30s 定时不阻塞测试（fake timers）。
3. gateway：在线走网关；4010 静默落直连；4030 向上抛不重试；离线直接直连。
4. ModeBanner：offline 渲染本地模式文案+重试按钮；online 渲染档位。
5. PrivacyIndicator：点击展开解释；跳设置按钮触发 setView。
6. 回归：既有 156 项仍全绿（`npm test` ≥156 通过为 AC-19）。
